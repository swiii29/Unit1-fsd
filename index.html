What is Full Stack Development?

⭐⭐⭐ Important
🚀

Definition

Full Stack Development is the process of designing, creating, testing and deploying a complete web application from start to finish.

It involves front-end, back-end and database development.

🎨

Front-End

The part of the application that the user sees and interacts with.

HTML CSS JavaScript
⚙️

Back-End

Handles business logic, application workflows and request-response processing.

Java Python Node.js
🗄️

Database

Stores application data such as users, products and transactions.

MySQL MongoDB
💡 Simple Example

In an online shopping website:

  • Product page → Front-End
  • Order processing → Back-End
  • Customer/order data → Database

Software Engineer vs Full Stack Developer

👨‍💻 Software Engineer

Software engineering is a general term. A software engineer may work on a specific module or technology.

🚀 Full Stack Developer

Full Stack Development is part of software engineering and requires front-end and back-end knowledge for end-to-end applications.

Advantages & Disadvantages

✅ Advantages

  • Complete project ownership
  • Saves time and cost
  • Faster bug fixing
  • Easy knowledge transfer
  • Better division of work

⚠️ Disadvantages

3-Tier Architecture

⭐⭐⭐⭐⭐ Must Know
🏗️

Definition

3-Tier Architecture divides an application into three separate layers based on their responsibilities.

01

Presentation

UI & user interaction

→
02

Business

Rules & application logic

→
03

Data Access

Database communication

→
🗄️

Database

Stores data

01

Presentation Layer

Handles UI and interaction with the user.

HTML CSS JavaScript
02

Business Layer

Contains business rules and application logic.

Java Python
03

Data Access Layer

Communicates with the database using data access operations.

SQL DDL DML
🚨 VERY IMPORTANT RULE:

Presentation cannot directly access the Database. Business cannot directly access the Database.

Correct flow: Presentation → Business → Data Access → Database
📌 Diagrams: Page 7 — 3-Tier Architecture
Page 9 — Requests & Responses
07

Rules of 3-Tier Architecture

01 Each layer should be maintained separately.
02 Each layer contains only its own type of logic.
03 Presentation communicates only with Business.
04 Business communicates with Presentation and Data Access.
05 Data Access communicates with Business and DBMS.
06 Layers should be unaware of the internal workings of other layers.
🧠 Remember: P → B → D Presentation → Business → Data Access

JSON

⭐⭐⭐⭐⭐ Must Know
📦

JavaScript Object Notation

JSON is a lightweight, text-based, human-readable and language-independent data-interchange format. 

{
  "name": "Rahul",
  "age": 20,
  "student": true
}
{ } Object
[ ] Array
: Key → Value
, Separator

JSON Features

Simplicity Openness Self-Describing Internationalization Extensibility Interoperability

Why use JSON?

⚡

Less Verbose: More compact than XML.

🚀

Faster: Requires less data and parsing overhead.

👀

Readable: Simple and straightforward structure.

🌐

Network Communication: Commonly used to transmit data between server and web application.

REST Constraints

Separation

Statelessness

Server does not depend on previous client requests.

03

Cacheability
